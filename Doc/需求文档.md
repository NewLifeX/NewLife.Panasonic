# NewLife.Panasonic 需求文档

> 版本：v2.0 | 日期：2026-07-22

本文档描述 NewLife.Panasonic 的愿景、核心目标和功能方向。完成状态在[功能清单](功能清单.md)中追踪，详细设计在[架构设计](架构设计.md)中展开。

## 1. 背景与愿景

### 1.1 系统定位

松下 PLC 协议库，基于 NewLife.IoT 标准框架，为 .NET 应用提供松下 PLC 设备的多种通信驱动（Modbus TCP / Modbus RTU / Mewtocol TCP）。

作为 NewLife IoT 生态中的 PLC 驱动组件，与 NewLife.Modbus（Modbus 协议栈）、NewLife.ModbusRTU（串口 Modbus）和 NewLife.IoT（IoT 标准接口）协同工作。

### 1.2 愿景

成为 .NET 生态下松下 PLC 通信的首选驱动库，与 NewLife 物联网平台（IoTEdge、ZeroIoT）无缝集成，为工业自动化场景提供稳定、高效的设备连接能力。

## 2. 核心目标

| 编号 | 目标 | 所属层级 | 一句话描述 |
|------|------|----------|------------|
| PLC | 松下PLC协议驱动 | 基础层 | 三协议合一驱动（Modbus TCP / Modbus RTU / Mewtocol TCP），覆盖松下 PLC 主流通信场景 |

## 3. 功能需求

### 3.1 PLC — 松下PLC协议驱动

- **PLC-1 PanasonicDriver 统一驱动入口**：松下 PLC 驱动入口，实现 `IDriver` 接口，根据参数自动选择 Modbus TCP 或 Modbus RTU 通道。
- **PLC-2 PanasonicNode Modbus 节点**：Modbus 设备节点，实现 `INode` 接口，表示一台松下 PLC 设备，承载通道、地址、功能码等运行时状态。
- **PLC-3 PanasonicParameter 连接参数配置**：统一连接参数，实现 `IDriverParameter` 和 `IDriverParameterKey` 接口，支持 TCP 和 RTU 两种模式的参数配置与连接复用。
- **PLC-4 Mewtocol TCP 原生协议**：通过 Mewtocol 原生协议 TCP 通道直连松下 PLC，支持 RCP/WCP（寄存器读写）和 RCS/WCS（触点读写）命令。
- **PLC-5 连接健康检查与自动重连**：在 `PanasonicDriver` 中内建心跳检测、断线自动重连和超时重试机制（仅 Modbus TCP 模式）。
- **PLC-6 Modbus RTU 串口支持**：通过 Modbus RTU 协议支持串口（RS232/485）连接松下 PLC Modbus 网关，与 TCP 模式共用同一驱动入口。

## 4. 🧊 暂缓清单

| 功能 | 暂缓理由 | 解冻前提 |
|------|----------|----------|
| Mewtocol 串口支持 | Mewtocol 串口直连场景需求较少，当前已通过 Modbus RTU + Modbus 网关覆盖串口场景 | 有明确客户需求或 Mewtocol 串口场景占比较高时重新评估 |
| 数据订阅模式 | 实时数据变化订阅在边缘网关场景有价值，但可通过 IoTEdge 轮询替代 | IoTEdge 生态需要推送能力时 |
| Mewtocol 高级命令 | Mewtocol 完整协议复杂，当前 RCP/WCP/RCS/WCS 满足基本读写需求 | 有客户明确需要 HELP、RUN/PROG 切换等高级命令时 |

## 5. 不做什么

- 不实现松下 PLC 的底层串口协议（如 RS232/RS485 直接通信），仅通过 Modbus TCP 网关或 Modbus RTU 标准协议通信。
- 不包含 Web 管理界面或可视化配置工具。
- 不包含松下 PLC 的专用编程功能（如上传/下载梯形图程序、RUN/PROG 模式切换等 Mewtocol 高级命令）。
- 不支持松下 MEV/MEW 专用协议（非 Modbus 网关的非标协议，由竞品 HslCommunication 等覆盖）。
- 不追求覆盖所有 PLC 品牌（由 NewLife.Siemens 等兄弟组件负责）。
